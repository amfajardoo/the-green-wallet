# Data Model: Income and Expense Transactions

## Transaction

| Field | Type | Rules |
|---|---|---|
| `id` | `string` | Stable session identifier, generated by the store. |
| `type` | `income \| expense` | Determines the signed balance effect. |
| `accountId` | `string` | Must reference an existing account. |
| `money` | `Money` | Exact amount and explicit account currency; amount must be greater than zero. |
| `occurredAt` | ISO `string` | Valid date, normalized at the form boundary. Future dates are allowed. |
| `description` | `string` | Trimmed and nonblank; retained as posted audit metadata. |
| posted state | implicit | Transactions are posted immediately; there is no draft/edit/delete lifecycle. |

## Transaction Input

The form boundary accepts strings for `type`, `accountId`, amount, date, and description. Exact money parsing happens only after account and currency rules pass; invalid input never reaches the store mutation.

## Account Balance Projection

For one account and one currency:

```text
opening balance + income - asset expenses - card expenses
```

Card expenses increase the credit-card liability as a positive owed balance. No transaction may mix currencies or implicitly convert between COP and USD.

## Transaction Summary

The read model exposes account identity, name, type, currency, current derived balance, and newest-first transaction entries. COP and USD summaries remain separated.

## State Transitions

```text
invalid input -> validation error + unchanged state
valid input   -> transaction entity + derived account projection in one atomic update
session reset -> accounts and transactions cleared together
```
