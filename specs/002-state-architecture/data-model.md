# Data Model: Shared Client State Architecture

## Account

| Field | Type | Rules |
| --- | --- | --- |
| `id` | `string` | Stable for the active session; generated by the store sequence |
| `name` | `string` | Trimmed display name; must contain non-whitespace text |
| `normalizedName` | `string` | Trimmed lowercase comparison key; not user-editable |
| `type` | `AccountType` | `savings`, `checking`, `cash`, or `credit-card` |
| `currency` | `Currency` | `COP` or `USD` |
| `balance` | `Money` | Zero or positive opening amount in the account currency |
| `openingBalance` | `Money` | Same exact amount as the opening event |
| `openingBalanceEvent` | `OpeningBalanceEvent` | Traceable event created atomically with the account |

Asset account types (`savings`, `checking`, `cash`) expose `balance` as available funds.
`credit-card` exposes it as outstanding liability. The state never combines currencies.

## Money

```text
currency: Currency
minorUnits: bigint
```

COP has scale 0; USD has scale 2. `minorUnits` is never negative in this feature.

## OpeningBalanceEvent

```text
id: string
kind: "opening-balance"
amount: Money
```

The event ID is derived from the account ID and is created in the same successful state
transition. It provides the origin of the initial displayed balance without introducing a
future transaction ledger prematurely.

## AccountSummary

```text
currency: Currency
availableMinorUnits: bigint
outstandingMinorUnits: bigint
```

Summaries are computed independently for COP and USD. Asset accounts contribute to
`availableMinorUnits`; credit cards contribute to `outstandingMinorUnits`.

## State transitions

```text
empty --valid create--> account added + opening event + derived values updated
empty --invalid create--> empty unchanged + typed error returned
populated --valid create--> previous accounts + one complete account
populated --invalid create--> complete previous state unchanged + typed error returned
populated --reset--> empty deterministic state
```
